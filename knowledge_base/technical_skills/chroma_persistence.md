# Chroma 本地持久化
Chroma 的 PersistentClient 把数据保存到指定磁盘目录，适合本地开发与测试。官方建议生产场景优先使用服务端部署。

## 索引维护
集合中的记录可以通过 ID 读取、更新或删除。本项目使用文件相对路径和分块序号生成稳定 ID，并比较内容指纹以跳过未变化的块。该策略是项目实现选择。

## 本项目更新文档后如何处理旧片段
以下是本项目 rag_chroma.py 的实现规则，不是 Chroma 自动提供的同步策略。
运行 build 后，程序以文件相对路径和块序号生成稳定 ID，比较正文与元数据的指纹。未变化的块跳过 Embedding，变化的块重新编码并通过 upsert 写入。
所有变化块编码成功后才开始写入。写入完成后，程序比较新旧 ID，删除已移除文件或缩短文档留下的过期片段。只清理派生索引，不删除原始文档。
空目录、目录不存在或元数据无效时中止构建，保留已有索引。多批写入并非整库事务，中断后需重新执行 build。更新时应停止服务，完成后重启。

## 模型一致性
查询向量必须与文档向量来自同一向量空间。更换模型时本项目创建独立集合，避免把不同模型的向量混合。索引是可重建数据；原始 Markdown 文档应独立保存。
